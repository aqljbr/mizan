# Four candidate UX concepts, round 2

## Shared platform: identical in ALL four concepts (judge only how each concept organises it)
- **Data items:** a plain name; why we need it; how to get it (step-by-step for common tools); a *Must have* or *Helpful* label; [Upload] button; [Connect account]; [Someone else has this → invite them] (the invitee gets a data-only login and a pending/done state); [We don't have it → what happens instead]. Upload errors say what's wrong, with a text example of a correct file. After an upload: "We read 12,430 rows, Jan–Dec 2025, columns: …". Autosave everywhere.
- **Waiting states** distinguish "waiting on you", "waiting on your IT/approver (expected)" and "we're working, expected Thu 16 Oct".
- **Report:** a one-paragraph answer, recommended steps, "How sure are we?" per finding (Strong / Moderate / Weak / Not yet tested, with a reason and what would make it stronger). Every number is tagged with its source file and date, or as an ASSUMPTION. [Ask a question] on each finding. Export to PDF and Word in English or Arabic (RTL).
- **Before signing up:** price, turnaround, a sample report, and a security and data-handling one-pager (English and Arabic).
- **Notifications:** email or WhatsApp (client's choice), only when the client must act or a result is ready, with a link straight to the action.
- **Approver:** every finding shows its evidence, source and date per number, the independent checker's verdict, and warnings (old data, untraced number). Release is blocked until every warning is resolved. Approval works per finding, with "approve all clean". The system flags clients silent for more than 48h (separate from expected waits).
- Accessible to WCAG 2.2 AA (headings, keyboard, text status, persistent errors), on mobile and desktop.

## Concept W
**Client:** everything happens in one conversation with the consultant. It starts with "What's the problem you want solved?", and follow-up questions come one at a time. The "what we understood" summary, each data item, waiting updates and the final report all arrive as messages in the thread, with the shared buttons on them. Typing "what do you still need?" makes the consultant reply with a list of outstanding items.
**Approver:** an inbox of conversation threads, sorted with flagged threads (warnings, silent clients, held messages) on top. Opening one shows the thread, and held items expand in place with the shared review panel.

## Concept X
**Client:** one page per engagement. At the top is a "Your next step" card (one action, its owner, and a time estimate), then a progress tracker in words (Understand → Data → Analysis → Checking → Consultant review → Report). Below: "What we understood" (editable lines), the data checklist, and the report when ready (it moves to the top, and finished sections collapse). The start is a single text box for the problem, then 3–5 follow-up questions on the same page.
**Approver:** a "Needs you" queue sorted by urgency. Opening an item shows the shared review panel, finding by finding.

## Concept Y
**Client:** a 5-step guided form (company, problem category and description, goals with suggestions, constraints, review), saved as a draft. Then a data page (a table of the data items with the shared actions), then a dashboard with tiles: status, data completeness %, analysis progress %, early charts, messages. The report is viewable online and as a formal document.
**Approver:** an admin table of all engagements (client, stage, % data, last activity, flags), sortable by flags. Opening a row shows the report editor with the shared review panel.

## Concept Z
**Client:** starts as a conversation: "What's the problem?", with follow-ups one at a time, like texting. Once the consultant has understood the problem (usually 5–10 minutes), it creates the engagement page and the conversation moves to a side panel. The page has a "Your next step" card (action, owner, time) at the top, a progress tracker in words, "What we understood", the data checklist and the report (which moves to the top when ready). The side panel stays open for questions at any time ("why do you need this?", "what does this finding mean?"); answers can turn into page changes.
**Approver:** a "Needs you" queue sorted by urgency, with the shared review panel per finding. Client questions from the side panel that would change an approved finding appear in the queue.
